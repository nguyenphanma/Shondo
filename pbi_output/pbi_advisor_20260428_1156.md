## 1. Naming Convention

**Pattern chính:**
```
{domain}_{MetricName}_{modifier}
```

| Domain prefix | Bảng chứa | Ví dụ |
|---|---|---|
| `mkt_` | _MKT_Measures | `mkt_Spend_Paid_LY` |
| Không prefix | sale_final | `Revenue`, `Total Qty` |
| `_W` suffix | sale_weekly | `Revenue_W`, `AOV_W` |
| Không prefix | stock_current/pen | `total_stock`, `moh` |

**Vấn đề naming hiện tại:**
- ❌ **Inconsistent**: sale_final dùng cả `Revenue LY` (có space) lẫn `Revenue_Ndays` (có underscore), lẫn `YoY rvn Growth %` (viết thường lẫn lộn)
- ❌ **Mixed case**: `Total Qty` vs `total_stock` vs `mkt_Reach`
- ❌ **Modifier không nhất quán**: LY modifier đôi dùng `_LY`, đôi dùng space `" LY"`, đôi dùng `_ly`
- ❌ `views_total` / `views_total_ly` không có prefix `mkt_`

## 4. Measures Cần Tối ưu / Có Vấn đề

### 🔴 Logic sai / Misleading

**`mkt_CPA_Paid_YoY%`** — dùng **phép trừ tuyệt đối**, không phải %:
```dax
-- Hiện tại (SAI tên):
mkt_CPA_Paid_YoY% = [mkt_CPA_Paid] - [mkt_CPA_Paid_LY]

-- Nên sửa thành:
mkt_CPA_Paid_YoY% = DIVIDE([mkt_CPA_Paid] - [mkt_CPA_Paid_LY], [mkt_CPA_Paid_LY])
-- Hoặc đổi tên thành mkt_CPA_Paid_YoY_Diff
```

**`Qty Growth % 90D`** — mẫu số dùng current thay vì LY:
```dax
-- Hiện tại (nghi vấn):
Qty Growth % 90D = DIVIDE([Qty_Ndays] - [Qty_Ndays_LY], [Qty_Ndays])  -- chia current!

-- Nên là:
= DIVIDE([Qty_Ndays] - [Qty_Ndays_LY], [Qty_Ndays_LY])
```

### 🟡 Thiếu CALCULATE wrapper / Date context không nhất quán

**MKT measures dùng 2 loại time intelligence khác nhau:**
```dax
-- Nhóm 1: dùng SAMEPERIODLASTYEAR (cần Calendar relationship)
mkt_Impressions_Paid_LY = CALCULATE(..., SAMEPERIODLASTYEAR('Calendar'[Date]))

-- Nhóm 2: dùng DATEADD trực tiếp trên fact table column (không qua Calendar!)
mkt_Engagement_LY = CALCULATE([mkt_Engagement], DATEADD(pbi_social[metric_date], -1, YEAR))
mkt_Spend_Paid_LY = CALCULATE([mkt_Spend_Paid], DATEADD(pbi_ads[metric_date], -1, YEAR))
```
⚠️ **Rủi ro**: Khi filter qua Calendar slicer, nhóm 2 có thể không phản ứng đúng. Nên chuẩn hóa về `SAMEPERIODLASTYEAR('Calendar'[Date])` nếu đã có relationship.

### 🟡 Measures trùng chức năng

```
[sale_final] TotalCustomers  vs  [sale_final] Customer Count
-- Cả 2 đều = DISTINCTCOUNT(sale_final[customer])
-- Nên gộp 1, xóa cái còn lại
```

```
[sale_final] ReturningRate  vs  [sale_final] returning_customer_rate_total
-- Cần kiểm tra xem logic có khác nhau không, nếu giống → gộp
```

### 🟡 Hardcode magic numbers

```dax
-- Nhiều measures hardcode 30 days thay vì dùng WindowDays parameter:
qty_30d        -- VAR _Start = _End - 29  (hardcode)
asp_30d        -- VAR _Start = _End - 29  (hardcode)
sales_per_day_sole  -- _Today - 30 (hardcode)

-- Nên dùng: VAR N = SELECTEDVALUE(WindowDays[Value], 30)
```

### 🟢 Cải thiện nhỏ

```dax
-- mkt_Follower: LASTNONBLANKVALUE có thể chậm với data lớn
-- Nên thêm CALCULATE wrapper để tận dụng filter context tốt hơn

-- missing_revenue_target: nên thêm IF để tránh negative display khi chưa có KPI
missing_revenue_target = 
    VAR gap = TargetRevenue - ActualRevenue
    RETURN IF(TargetRevenue = 0, BLANK(), gap)
```

## 🔴 [Measures cần tối ưu] {#fix}

### Fix: mkt_CPA_Paid_YoY% (sai công thức — đang dùng phép trừ tuyệt đối)

```dax
-- Sửa từ phép trừ tuyệt đối → % thay đổi thực sự so với LY
mkt_CPA_Paid_YoY% = 
    DIVIDE(
        [mkt_CPA_Paid] - [mkt_CPA_Paid_LY],
        [mkt_CPA_Paid_LY]
    )
```

> **Giải thích:** Công thức cũ trả về số tuyệt đối (VD: -5,000đ) thay vì % (-12%). Đây là KPI "lower is better" nên YoY% âm = tốt hơn.

---

### Fix: Qty Growth % 90D (sai mẫu số — đang chia current thay vì LY)

```dax
-- Mẫu số phải là LY để tính % tăng trưởng đúng nghĩa
Qty Growth % 90D = 
    DIVIDE(
        [Qty_Ndays] - [Qty_Ndays_LY],
        [Qty_Ndays_LY]   -- LY làm base, không phải current
    )
```

> **Giải thích:** Growth % = (Current - Base) / Base, base phải là LY. Dùng current ở mẫu số sẽ cho kết quả sai lệch, đặc biệt khi tăng trưởng mạnh.

---

### Fix: mkt_Engagement_LY & mkt_Spend_Paid_LY (chuẩn hóa về Calendar)

```dax
-- Chuẩn hóa: dùng SAMEPERIODLASTYEAR qua Calendar thay vì DATEADD trực tiếp trên fact column
mkt_Engagement_LY = 
    CALCULATE(
        [mkt_Engagement],
        SAMEPERIODLASTYEAR( 'Calendar'[Date] )
    )
```

```dax
-- Tương tự cho Spend để đảm bảo Calendar slicer hoạt động đúng
mkt_Spend_Paid_LY = 
    CALCULATE(
        [mkt_Spend_Paid],
        SAMEPERIODLASTYEAR( 'Calendar'[Date] )
    )
```

> **Giải thích:** DATEADD trực tiếp trên `pbi_ads[metric_date]` bỏ qua relationship với Calendar table → slicer theo Calendar không filter đúng. Chuẩn hóa về `SAMEPERIODLASTYEAR('Calendar'[Date])` đảm bảo nhất quán.

## 🔴 [Measures mới] — SALE: Bills/Orders {#bills}

### Bills trong sale_final

```dax
-- Đếm số đơn hàng (bills/orders) từ sale_final, bổ sung khoảng trống hiện tại
Bills = 
    DISTINCTCOUNT( sale_final[bill_id] )
```

> **Giải thích:** Hiện tại Bills chỉ có trong `sale_weekly`, thiếu hoàn toàn trong `sale_final` khiến không thể phân tích orders theo channel/category.

---

```dax
-- Số đơn hàng cùng kỳ năm ngoái
Bills_LY = 
    CALCULATE(
        [Bills],
        SAMEPERIODLASTYEAR( 'Calendar'[Date] )
    )
```

> **Giải thích:** Base so sánh LY cho số đơn hàng.

---

```dax
-- % tăng trưởng số đơn hàng so với cùng kỳ năm trước
Bills_YoY% = 
    DIVIDE(
        [Bills] - [Bills_LY],
        [Bills_LY]
    )
```

> **Giải thích:** KPI quan trọng để đánh giá tăng trưởng order volume độc lập với AOV.

---

```dax
-- Số đơn hàng tháng trước (PM = Previous Month)
Bills_PM = 
    CALCULATE(
        [Bills],
        DATEADD( 'Calendar'[Date], -1, MONTH )
    )
```

> **Giải thích:** So sánh MoM cho số đơn hàng.

---

```dax
-- % thay đổi số đơn hàng so với tháng trước
Bills_MoM% = 
    DIVIDE(
        [Bills] - [Bills_PM],
        [Bills_PM]
    )
```

> **Giải thích:** Trend ngắn hạn của order volume.

---

```dax
-- Số đơn trong N ngày gần nhất (dùng WindowDays parameter)
Bills_Ndays = 
    VAR _End   = MAX( 'Calendar'[Date] )
    VAR _N     = SELECTEDVALUE( WindowDays[Value], 90 )
    VAR _Start = _End - _N + 1
    RETURN
        CALCULATE(
            [Bills],
            'Calendar'[Date] >= _Start,
            'Calendar'[Date] <= _End
        )
```

> **Giải thích:** Bổ sung Bills vào bộ Ndays analytics, dùng WindowDays parameter thay vì hardcode.

---

```dax
-- Số đơn Ndays cùng kỳ năm ngoái
Bills_Ndays_LY = 
    VAR _End   = MAX( 'Calendar'[Date] )
    VAR _N     = SELECTEDVALUE( WindowDays[Value], 90 )
    VAR _Start = _End - _N + 1
    VAR _StartLY = DATE( YEAR(_Start) - 1, MONTH(_Start), DAY(_Start) )
    VAR _EndLY   = DATE( YEAR(_End)   - 1, MONTH(_End),   DAY(_End)   )
    RETURN
        CALCULATE(
            [Bills],
            'Calendar'[Date] >= _StartLY,
            'Calendar'[Date] <= _EndLY
        )
```

> **Giải thích:** So sánh LY cho Bills trong rolling window.

```dax
Revenue_W_YoY% =

        [Revenue_W_LY]
```

```dax

qty_w_LY =

    )
```

> **Giải thích:** Base LY cho weekly quantity analysis.

---

```dax
-- % tăng trưởng số lượng tuần so với cùng kỳ năm trước
qty_w_YoY% =
```

```dax
-- Số đơn hàng theo tuần cùng kỳ năm trước
bills_w_LY =
```
